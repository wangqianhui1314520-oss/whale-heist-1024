# 《鲸鱼魔盗团》游戏音频制作方案

> 1024 超能 Coding 周末 · 游戏赛道 · 音频补全计划（方案稿）
> 日期：2026-10-25 | 状态：待确认后执行

## 一、范围与现状盘点

### 1.1 目标游戏

项目文件夹 `1024切磋大会` 下有两个游戏目录，结论如下：

| 目录 | 状态 | 是否本次音频目标 |
| --- | --- | --- |
| `游戏-鲸鱼魔盗团` | 完整可玩网页游戏：五章主线、四角色、双端、完整美术资产、已有程序化音频模块 | **是（唯一目标）** |
| `游戏-大肥鱼指令不清` | 仅策划案 V1.0（`docs/大肥鱼指令不清最终策划案.md`），`src/` 为空，无游戏本体 | 否。无本体可做，若日后做出本体再补 |

### 1.2 现有音频能力（`src/game/audio.mjs`）

| 项目 | 现状 |
| --- | --- |
| 引擎 | 纯 Web Audio API 程序化合成，无任何音频资源文件 |
| 背景音乐 | 每 4 秒循环的三音正弦和弦（`harbor` / `evacuation` 两套），默认音量 0.25 |
| 音效 | 16 个预置，均为单振荡器扫频（dash / impact / pickup / delivery / command-confirm / alarm / results / jump / ui / door / story / story-page / story-scan / story-impact / story-alert / story-beacon） |
| 已接入能力 | 首次操作解锁、三档音量（总/音乐/音效）、静音、暂停、失焦处理、按章节切场景（第 5 章切 `evacuation`）、事件队列触发 `audio.play(name)` |

### 1.3 缺口（本次要解决的）

1. **没有旋律性音乐**——BGM 是正弦和弦垫，无情绪、无主题动机、四秒一循环过于机械；
2. **没有环境音**——水港、机房、警戒氛围缺失；
3. **音色单薄**——所有音效是单波形扫频，无层次、无材质感，与已有高完成度美术不匹配；
4. **无语音**——策划案允许"语音改字幕"降级，语音列为可选；
5. **资产零登记**——策划案要求"登记图像、声音和第三方资源"，音频目前无来源记录。

## 二、音频设计定位

整体跟随美术与剧情的"诙谐海港 × 机房电子 × 喜剧夸张"基调：

| 维度 | 定位 |
| --- | --- |
| 风格 | 轻爵士/手风琴海港小调（主角感）＋ 电子脉冲（机房/警戒感）＋ 卡通夸张音效（Q 版反馈） |
| BGM 情绪曲线 | 标题(诙谐轻松) → 1–3 章(轻快带悬念) → 4 章(反转紧张) → 5 章(撤离紧迫) → 结算(滑稽加冕) |
| SFX 原则 | 短促、夸张、有材质（水花/金属/纸张/电子），单次 0.1–0.5 秒 |
| 响度基准 | BGM −20 dB 左右垫底，环境 −28 dB，SFX 峰值 −8 dB，语音 −12 dB（相对主音量） |
| 循环要求 | 所有 BGM/环境音必须无缝循环（AI 生成后用编辑对齐，或叠加淡入淡出拼接） |

## 三、音频资产体系

### 3.1 音乐层（BGM）

| ID | 场景/状态 | 情绪 | 制作要点 | 目标时长 |
| --- | --- | --- | --- | --- |
| `bgm_title` | 标题 / 主菜单 | 诙谐欢快，海港阳光 | 手风琴＋轻鼓点＋水花点缀，循环尾接首 | 30s 循环 |
| `bgm_harbor` | 第 1–3 章行动 | 轻快带悬念 | 轻爵士节奏＋滴水音色，留空间给音效 | 45s 循环 |
| `bgm_investigation` | 第 4 章战报公开 | 悬疑紧迫 | 低频弦乐脉冲＋滴答声，逐渐加密度 | 45s 循环 |
| `bgm_evacuation` | 第 5 章 60 秒撤离 | 高速紧迫 | 电子脉冲加速，BPM 明显高于港口曲 | 60s 循环 |
| `bgm_results` | 章末结算 / 总评 | 滑稽加冕号角 | 小型铜管上行号角，收尾干净 | 12–20s 非循环 |
| `bgm_failure` | 失败结算 | 诙谐懊恼 | 低音拨弦"哇哇"＋短弱奏 | 8–12s 非循环 |
| `bgm_story` | 剧情演出 | 叙事轻垫 | 弦乐/钢琴长音垫，可循环 | 30s 循环 |

### 3.2 环境音层（Ambience）

| ID | 用途 | 内容 | 目标时长 |
| --- | --- | --- | --- |
| `amb_harbor` | 港口常驻氛围（1–4 章） | 轻浪、水滴、远处气笛 | 30s 循环 |
| `amb_ops` | 机房运转氛围（叠加） | 服务器嗡鸣、键盘/散热底噪 | 30s 循环 |
| `amb_alarm` | 警戒 ≥70 时叠层 | 低频嗡鸣＋雷达脉冲 | 15s 循环 |

### 3.3 动作音效层（SFX，与现有 `play()` 名称一一对应）

保留现有 16 个触发名不变（代码改动最小），逐条给出目标音色：

| 触发名 | 场景 | 目标音色 |
| --- | --- | --- |
| `dash` | 鲸形冲刺 | 水花滑行"唰"＋气泡，清亮 |
| `impact` | 撞开数据节点/破障 | 玻璃罐碎裂＋低频砰，有金属尾音 |
| `pickup` | 数据吸附入包 | 吸附"啵"＋轻微电子收束 |
| `delivery` | 交付数据 | 确认"叮"＋小号上行两音 |
| `command-confirm` | 指令确认 | 战术确认电子音，区别于交付 |
| `alarm` | 警戒器报警 | 高频双音脉冲（可循环 2–3 次） |
| `results` | 结算播报 | 加冕号角（与 bgm_results 呼应） |
| `jump` | 跳跃/爬梯 | 轻弹跳音 |
| `ui` | 通用 UI 点击 | 柔和纸感"咔哒" |
| `door` | 房间切换/登艇 | 舱门气动"嘶—砰" |
| `story` | 剧情翻页/推进 | 纸页翻动＋提示音 |
| `story-page` | 剧情对话框 | 短促打字/翻页 |
| `story-scan` | GLM 扫描 | 电子网格扫描扫频 |
| `story-impact` | 剧情中破障 | 低沉撞击 |
| `story-alert` | 剧情中警报 | 略柔和的警报变体 |
| `story-beacon` | 返航信标 | 灯塔脉冲"叮—嘟" |

### 3.4 语音层（可选，P2）

策划案允许"语音改字幕"，语音不做交付硬性要求。若做：四角色各 5–8 条中文短句（指令确认、加入、撤离提示、结算吐槽），每条 1–3 秒，AI 合成人声。

## 四、场景-事件-音频映射

| 界面/事件 | 音乐 | 环境 | 音效 |
| --- | --- | --- | --- |
| 标题/主菜单 | `bgm_title` | — | ui |
| 第 1–3 章行动 | `bgm_harbor` | `amb_harbor`（室内叠加 `amb_ops`） | 动作类全部 |
| 第 4 章战报公开 | `bgm_investigation` | `amb_harbor`＋`amb_ops` | 同上＋story-alert |
| 第 5 章撤离 60s | `bgm_evacuation` | `amb_alarm` 叠层 | alarm 高频化 |
| 剧情演出 | `bgm_story`（暂停行动音乐） | 视章节保留氛围 | story 系列 |
| 章末结算 | `bgm_results` | 停止环境 | results |
| 失败 | `bgm_failure` | 停止环境 | impact |
| 警戒 ≥70 | 现音乐不动 | 叠加 `amb_alarm` | 预告扫描音 |
| 暂停/失焦 | 音乐衰减暂停 | 暂停 | — |

## 五、制作管线

1. **生成**：用 AI 音频工具按资产卡逐条生成 WAV（音乐、音效、环境声；语音另用合成人声）。每条资产卡记录目标、情绪、风格参考与时长。
2. **转码压缩**：ffmpeg 统一转码 —— BGM/环境 96kbps 立体声、SFX 128kbps 单声道、语音 96kbps 单声道，全部 MP3；长文件按循环点裁剪对齐，验证无缝。
3. **落盘**：`assets/audio/{music,ambience,sfx,voice}/`，命名与资产 ID 一致。
4. **登记**：`assets/provenance/audio-manifest.json`，逐条记录工具、日期、生成 prompt、时长、用途、游戏内引用点（满足策划案"登记声音来源"要求）。
5. **打包**：`scripts/build-game.mjs` 纳入 `assets/audio` 复制到 `dist/`；更新 `assets/runtime-catalog.json` 登记音频资源。
6. **接入**：升级 `src/game/audio.mjs`（见下节），构建后跑回归验证。

### 体积预算（受"初始包 ≤8MB"目标约束）

| 类 | 数量 | 单条约 | 小计 |
| --- | --- | --- | --- |
| BGM（P0 三首＋P1 四首） | 7 | 0.3–0.6MB | ≤3.2MB |
| 环境音 | 3 | 0.2–0.3MB | ≤0.9MB |
| SFX | 16 | 5–20KB | ≤0.3MB |
| 语音（可选） | 20 | 10–30KB | ≤0.6MB |
| **合计** | — | — | **≤4.5MB（首批 P0 控制在 2MB 内）** |

## 六、代码接入设计（`src/game/audio.mjs` 升级）

**目标：不破坏现有调用方，向下兼容。**

1. **保留现有接口**：`unlock() / configure() / setMuted() / setScene() / setPaused() / play(name) / dispose()`，`main.mjs`、`ui-v3.mjs` 零改动即可继续工作。
2. **新增资源加载器**：启动时按需 `fetch + decodeAudioData` 加载音频到缓存池；短音效使用 `AudioBufferSourceNode` 即时触发（延迟可忽略），BGM/环境使用 buffer 循环节点实现无缝循环。
3. **`play(name)` 升级**：内部维护 `name → 资产文件（若有）`映射，有文件播文件；文件缺失/未加载完时**自动回退现有程序化合成**，保证不静默失败。
4. **新增 API**：`playMusic(id)`、`playAmbience(id)`、`stopMusic(fadeMs)`；场景音乐切换用 1.5 秒交叉淡变（`setScene()` 内部自动切 BGM）。
5. **混音总线**：master → music / ambience / sfx / voice 四个独立子总线，各自可独立调音量；设置页新增"环境音""语音"两档（保留现有三档字段兼容旧存档）。
6. **警戒联动**：暴露/警戒 ≥70 时由 `main.mjs` 触发 `audio.playAmbience('amb_alarm')`（或直接在 `setScene` 逻辑中按警戒值叠层）。
7. **静音/暂停/失焦**：沿用现有 gain 衰减逻辑，暂停时 BGM/环境同步静音，恢复时同步复原。

## 七、优先级与工作量

| 档 | 内容 | 资产数 | 说明 |
| --- | --- | --- | --- |
| **P0 必须** | `bgm_harbor`、`bgm_evacuation`、`bgm_results`＋核心 7 类 SFX（dash/impact/pickup/delivery/command-confirm/alarm/results）＋`amb_harbor`＋代码接入 | ≈11 条 | 先立起"有层次、有情绪"的声音骨架；对应策划案"七类声音必须覆盖" |
| **P1 推荐** | `bgm_title`、`bgm_investigation`、`bgm_story`、`bgm_failure`＋`amb_ops`、`amb_alarm`＋其余 9 类 SFX 补齐＋警戒联动 | ≈15 条 | 补全情绪曲线与氛围 |
| **P2 可选** | 四角色语音短句、结算语音播报 | ≤20 条 | 策划允许语音改字幕，不阻塞交付 |

预计总工作量：资产生成约 2 批（每批 10–15 条调用）、转码登记 1 批、代码接入与平衡 1 轮、回归验证 1 轮。P0 可在一个执行轮次内完成。

## 八、验证与验收

1. **资产层**：逐条试听；确认循环无缝（交叉点无爆音/断音）、时长与 ID 匹配、音量基准符合（BGM −20dB / SFX −8dB）。
2. **集成层**：浏览器实测——首次点击解锁、静音开关、三档音量独立生效、暂停/失焦暂停、第 4/5 章 BGM 自动切换（交叉淡变）、警戒报警叠层。
3. **回退层**：临时移除某条资产文件，确认该事件仍出程序化合成音（不静默）。
4. **性能与体积**：记录 dist 音频总字节；弱网下首包加载时间目标 <5s；内存中 buffer 数量不随章节累积（复用循环节点）。
5. **双端**：桌面键鼠与手机触屏各跑一遍首章教学，确认音效触发正常。
6. **来源登记**：`audio-manifest.json` 字段完整，可追溯到生成工具与 prompt。
